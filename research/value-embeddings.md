# Value embeddings

トークンごとの表を最後の層から1層おきに置き、注意の V に、key-value のヘッドごとのゲート（3·sigmoid）を通して足す。表の幅は key-value の幅。元の考えは ResFormer（value residual learning、arXiv 2410.17897）。

- nanochat の dev/LOG.md（commit 92d63d4e） 2026-01-17: 置き方は全部の層・1層おき・U字形・最初と最後の層だけを比べ、1層おきが最良。表を層で共有する、低ランクにする、射影で小さくする、はすべて悪化。ゲートは効く。ステップ数・計算量・時間のどれで比べても勝ち、最適なトークン数とパラメータの比が8から4に下がった。
- Marin speedrun の nano_arch_ablations（約1.5億〜2.8億パラメータ、Paloma C4 の BPB。前の行に1つずつ足していく比較）: value embeddings で −0.0105、ゲートでさらに −0.0045。
- 1層おきが全部の層より良い理由は、どの資料にも説明がない。
