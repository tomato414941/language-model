# CompleteP

Dey ら、Don't be lazy: CompleteP enables compute-efficient deep transformers（arXiv 2505.01618、2025）。Cerebras、Princeton、Harvard などの共著で、実験は Cerebras CS-3。

モデルの大きさを変えるときに、学習率や初期値などをどう調整するか（パラメータ化）を比べた研究。深さ L に応じて、各ブロックの出力を L^(−α) 倍する。α=1 が CompleteP で、LayerNorm とバイアスの学習率、weight decay、AdamW の ϵ の調整も含む。実装は EleutherAI の nanoGPT-mup の completep ブランチにある。

比べたのは、標準（SP）、幅だけを補正する µP、α=0.5、α=1 の4つ。

## 深さをまたいだ設定の移し替え

2層で決めた学習率と初期値を、そのまま128層まで使えたのは α=1 だけだった。ほかは深さごとに最適な値が変わった。1パラメータ20トークンまで学習すると、学習率への敏感さは小さくなった。

深いほど、α=1 は µP より少ない計算量で済む。埋め込みを除いて15億のモデルで、32層で11.8%、179層で34.4%の節約。3億では24層で約6%、36層で約10%（図から読み取り）。

## 形の比較

埋め込みを除いたパラメータ数をそろえて、幅と層を変えた。どれも1パラメータ20トークンで、バッチは計算量から決めている。SlimPajama、文脈2048、GPT-2 のトークナイザ、ヘッド幅64、FFN は幅の4倍、ReLU²、ALiBi、埋め込みは共有しない、AdamW。

最良の幅÷層は、5000万で32（512×16）、3億で42.7（1024×24）、15億で62（1984×32）。大きいモデルほど上がるが、この範囲では約60以下。α=0.5 は少し広い形を好む。

3億での、最良からの損失の増え方（図から読み取り）。計算量の違いは、損失と計算量の当てはめで差し引いてある。

| 幅×層 | 幅÷層 | α=1 | µP |
|---|---|---|---|
| 448×125 | 3.6 | +2.6% | +4.5% |
| 640×62 | 10.3 | +0.9% | +2.0% |
| 832×36 | 23.1 | +0.3% | +0.9% |
| 1024×24 | 42.7 | 0% | +0.3% |
| 1280×16 | 80 | +0.1% | +0.5% |
| 1600×10 | 160 | +0.8% | +1.1% |
| 2048×6 | 341 | +2.3% | +2.5% |
| 2880×3 | 960 | +6.5% | +6.5% |

最良から1%以内に収まる範囲は、大きいモデルほど深い側に広がる。15億では、α=1 で比11.8まで、µP で比38.7まで。

損失と計算量の当てはめは、α=1 で (F/1.0e27)^(−0.056)、µP で (F/1.4e27)^(−0.051)（F は学習全体の計算量）。

1パラメータ200トークンでも α=1 が一番低い。3億の 1024×24 は µP 2.451、α=1 2.443、448×125 は µP 2.537、α=1 2.497。

## 先行研究への見方

Kaplan らが比100付近を最適としたのは、SP で深いモデルが不利だったためだとしている。Gemstones（arXiv 2502.06857）が浅い形を最適としたのも、学習率の補正が不完全で深いモデルが不利だったためだとしている。

MoE、長い文脈、バッチ、勾配クリップ、LAMB、モメンタムについての理論は、今後の課題としている。
