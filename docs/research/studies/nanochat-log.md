# nanochat の LOG

karpathy/nanochat の dev/LOG.md（2026-01 から）。形や学習の変更を1つずつ試した記録で、ステップ、計算量、時間のそれぞれで比べている。d は層の数で、幅は層の64倍。

| 日付 | 試したこと | 結果 |
|---|---|---|
| 01-11 | 短い窓の層と長い窓の層を混ぜる | 入れた（根拠は短い実験だけ） |
| 01-11 | x0 lambdas、resid lambdas | 入れた（d8 で −0.0103、d20 で −0.0039） |
| 01-12 | Multi-token prediction | メモリ増、時間で負け |
| 01-13 | 数字の区切り（d12、語彙32K） | BPB は1桁 0.969、2桁 0.965、3桁 0.972 |
| 01-13 | 文書の中だけの注意（d16） | ほとんど差なし。入れない |
| 01-15 | Olmo の混ぜ方（d16） | CORE 15.5 → 13.8 |
| 01-16 | 半分の RoPE、非対称の softcap、Smear、Backout、スキップ接続 | どれも効かないか少し悪い |
| 01-17 | Value embeddings | 1層おきが最良。ステップ、計算量、時間のどれでも勝ち |
| 01-17 | 幅÷層（計算量 1e18 で固定） | 128 より 64 が良い |
| 01-17 | ヘッドの幅 | 64 より 128 が良い |
| 01-19〜22 | 最適化の約320の実験 | d12 で良かった値は d20 で悪くなる |
| 01-27、28 | バイグラムのハッシュの表 | d25 では差が小さく、取り除いた |
| 01-29 | MuonH、AdamH | 基準より悪い |
| 02-02 | FP8（torchao、tensorwise、d26） | 速さ1.17倍、同じ損失で比べると約5%。torch.compile が必須 |
| 02-03 | Adam を1ステップおきに更新 | 2%速いが、時間で少し負け |
| 02-05 | SwiGLU（d12、d24） | ReLU² より全部で悪い |
| 02-05 | バッチの自動の決め方 | Power Lines の法則で d18〜26 は 2^20 |
| 02-17 | FineWeb、FinePDFs の混ぜ方（d26） | CORE 0.2602 → 0.2241、0.2549 |
| 02-19 | MoE | ステップでは良いが、時間で負け |
| 03-02 | softcap の c | 20 が最良 |
| 03-04 | FineWeb-Edu → ClimbMix | GPT-2 の性能まで2時間46分 → 2時間1分 |
| 03-24 | Parameter Golf の案（LeakyReLU²、Partial RoPE、LN scale、直交初期化、XSA） | どれも時間で得にならない |
| 05-05 | DyT（d12） | ステップでも勝てず、速さは約10%落ちた |

同じ記録に、EMA や SWA は試して効かなかった（記録はしなかった）とある。
