# M-IFEval-Ja

日本語の指示に従えるかを、規則で採点する評価（tokyotech-llm/M-IFEval-Ja）。公式の採点コード（lightblue-tech/M-IFEval、commit 10b874d）で採点すると、公開されている Qwen2.5-0.5B と gpt-4o-mini の結果を、strict と loose のどちらも 172/172 で再現できた。llm-jp-eval v2.1.5 にも入っている（mif_eval_ja）。

指示は33種類で、1種類あたりおおむね7問ある（複数の指示がある問題は172問中44問）。箇条書きの数、段落数、JSON などの一般的な指示のほかに、ふりがな、漢字だけ、ひらがなだけ、カタカナだけ、漢数字、体言止め、文末の統一のような日本語に特有の指示がある。特有のものは9種類で、指示全体の約3割。他の言語で答えさせる問題は4問。

llm-jp-eval の既定の設定は、返答を最初の空行で切ってから採点する。公式の採点コードは返答全体を見る。2026-10-31 に、3億パラメータの自作モデルの返答を調べると、172件中124件が切られ、採点されたのは文字数の27%だった（文字数の中央値は628字から102字）。空行で段落を数える指示は、切られると満たせない。一方、使ってはいけない語の指示のように、短いほど有利なものもある。

同じモデルの同じ返答を両方の切り方で採点すると、最初の空行までは strict と loose がどちらも 0.186、返答全体では strict 0.209、loose 0.233 で、差は小さかった。同じ重みをもう一度評価すると、既定の点は 0.163 から 0.186 に動いた。172問の点はその程度揺れる。

llm-jp-eval v2.1.5 の strict と loose の関数は、どちらもループの中で return している。コードを読むかぎり、複数の指示がある問題（172問中44問）でも最初の指示しか見ない。実行して確かめてはいない。公式の採点コードは、返答を切らず、すべての指示を確かめる。

今の評価（instructions-ja-en-1）は、公式の採点コードで採点する。

公式リポジトリの入力ファイル（commit 10b874d の `data/ja_input_data.jsonl`）は、172問中7問で「3文以上」のように書いている。公開の返答と llm-jp-eval の問いは「3行以上」で、採点の規則はどの問いも同じ（2026-11-01 に v5 の記録と照らした）。今の評価は入力ファイルのとおり「文」で問う。公開の結果を再現して採点の環境を確かめるときだけ、7問を公開の返答が問われた「行」の文面に合わせる。
