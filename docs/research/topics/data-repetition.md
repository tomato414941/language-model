# 質の高いデータの繰り返し

同じデータを何回か繰り返して読む。

- [Fang ら](../sources/datasets-documents-repetitions.md)（arXiv 2503.07879）：学習の設定を適切に変えれば、厳しく選んだデータを10回まで繰り返すほうが、その10倍の量を1回読むより良かった。計算量を何桁も変えても同じだった。
- [MiniMax-01](../sources/minimax-01.md)（arXiv 2501.08313）：質の低いデータは2回を超えると大きく悪くなり、質の高いデータは4回まで効いた。
- [Xue ら](../sources/to-repeat-or-not.md)（arXiv 2305.13230、2023年）：繰り返すと過学習で悪くなる。悪くなり方には、データの量、モデルの大きさ、学習の目的が大きく効き、データの質の影響は小さかった。正則化はほとんど効かず、dropout だけがよく効いた。
- [繰り返し回数の研究](../sources/repetition-counts.md)（arXiv 2610.05126）：最良の回数はモデルの大きさで変わる。520M の Proof-Pile-2 では、16回より8回が少ないトークンで損失が低い。

[計算とデータのスケーリング則](../sources/compute-data-scaling.md)（14M〜600M）：繰り返しや書き直しの価値は、モデルの大きさ、パラメータあたりのトークン数、量で変わり、増やすと飽和する。約 600M 以下で 1× Chinchilla 未満では繰り返しより書き直しが良い。v6 は 520M で約 0.8× Chinchilla。

[データが足りない場合の設定の研究](../sources/data-constrained-hp-transfer.md)は、繰り返す学習では weight decay を大きさとエポック数に合わせ、複数のモデルの平均も使うとよいとした。結果は 1億トークンの学習で、文書を繰り返していない v7 までには当たらない。データを繰り返す世代で読み直す。見直し期限：2026-12-15。
