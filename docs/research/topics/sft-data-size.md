# 指示学習のデータ量

事前学習の Chinchilla のような、パラメータあたりのトークン数の目安は、2026-11-01 に探した範囲では見つからなかった。3回検索して読んだ範囲で、探し尽くしてはいない。

分かっていること。

- 損失はデータ量のべき乗で下がり、減り方は緩やかになる（[データの混ぜ方の研究](../sources/sft-data-mixing.md)、[Rectified Scaling Law](../sources/rectified-scaling-law.md)）。
- 事前学習は、ファインチューニングのデータ量を実質的に何倍にもする（[Scaling Laws for Transfer](../sources/scaling-laws-transfer.md)）。
- 7B と 8B では、ランダムに増やすと50万件まで点が上がり続けた。増えたのは広さ（[広さと深さの研究](../sources/sft-coverage-depth.md)）。
- 領域の最適な重みはデータ量によって変わる（データの混ぜ方の研究）。小さな学習で係数を当てはめて計算できる。0.5B も比べている。
- 特定の力に向けたデータは、なければ点が大きく下がる。8B で IFEval が 72.8 から 53.6（[Tülu 3](../sources/tulu-3.md)）。
- データの配分や足りない力の例の生成だけで、IFEval が +3.4〜6.5 上がった例がある（[AutoSFT](../sources/auto-sft.md)）。
- 同じトークン数なら、返答の割合が大きい例ほど役に立つ（[返答の割合の研究](../sources/sft-response-ratio.md)）。ただし 8B〜9B の LoRA の結果で、例を選ぶのは v6 のデータの決まりに反するので入れていない。決まりを変えるときに読み直す。見直し期限：2026-11-15。

分かっていないこと。

- 5億パラメータのモデルに要る指示学習の量。上の結果の多くは 7B 以上で、指標も違う。
- 日本語での結果。

v6 は約52万会話、学習対象は約2億トークンを2エポック読む。Tülu 3 の 8B は約94万会話。

データの種類の組み合わせについて。

- [方向のある転移の研究](../sources/directed-transfer-sft.md)：干渉する1種類が他の種類の効果の大半を打ち消す例がある。小さなモデルの少ない学習で組み合わせを選べ、他の大きさにも移せた。専門のコーパスの結果で、公開ベンチマークではない。v5 の指示学習で一部の点が下がった理由と関係するかは確かめていない。
- [Agaram](../sources/agaram.md)：指示学習を2通り足しても知識の指標は上がらなかった。
- [Metis-1.6](../sources/metis-1-6.md)：思考を削除して直接の答えを作ると、見えない途中の作業を前提にした例になり、点が下がった。

前の能力の維持について。

- [忘却の研究](../sources/continual-sft-forgetting.md)：LoRA の結果で、古い課題の例を混ぜると正解率が 5.43% でなく 97.83% に保たれ、新しい課題の点は変わらなかった。
- [段階を分けない学習](../sources/unified-training.md)：事前学習のデータと混ぜて学習すると元の能力を保った。

v5 の指示学習で JNLI と JCommonsenseQA が下がったことに当てはまるかは確かめていない。v6 の2本の点を見て、事前学習のデータを混ぜる案を検討する。見直し期限：2026-11-15。
