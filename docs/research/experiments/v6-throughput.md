# v6 の速さとメモリ

2026-11-01 に、v6 の学習設定を RTX 4090（23.5GiB）1台で測った。データは合成で、実際の文書の長さに合わせて区切りを入れた。データの読み込み、重みの保存、検証は含まない。

| 設定 | コンパイル | 結果 | 速さ（トークン/秒） | メモリ |
|---|---|---|---|---|
| 事前学習、bfloat16 | あり | 動いた | 35,249 | 17.4GiB |
| パッチ段階、bfloat16 | あり | 動いた | 146,483 | 18.4GiB |
| 事前学習、FP8 | あり | 勾配が非有限になって止まった | - | - |
| パッチ段階、FP8 | あり | 勾配が非有限になって止まった | - | - |
| 指示学習の形、bfloat16 | なし | 22.3GiB を確保した時点でメモリ不足 | - | - |

どれも1回に1窓を読む設定で、1窓は事前学習と指示学習が 8,192 トークン、パッチ段階が 32,768 トークン（8,192 パッチ）。速さは事前学習が1更新（128窓）、パッチ段階が2更新（64窓）の測定で、短い。

パッチ段階の速さは事前学習の4.16倍で、計算が4分の1になるという見込みに近い。

動いた2つのコンパイルには6〜8分かかった。FP8 は止まるまでに、事前学習で16分、パッチ段階で8分かかった。

FP8 の非有限の原因は分かっていない。CPU では、幅128、2層のモデルをコンパイルなしで10更新しても、幅256、2層のモデルをコンパイルして1回逆伝播しても再現しなかった。GPU での切り分けはしていない。

1152×24 の形、2窓、GPU が必要なテストは、45分の上限に達して結果を取れなかった。
