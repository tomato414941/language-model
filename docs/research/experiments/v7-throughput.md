# v7 の速さとメモリ（RTX 5090）

2026-11-05 に、v7 の候補の形を Vast の RTX 5090（32GB）1台で測った（`runs/profile-v7`、`runs/profile-v7-moe`）。どれもコンパイルあり、Hyperball（倍率10）、出力の行列は乱数から始める。データは合成で、文書は Web の平均と同じ約1,325トークンで区切り、各文書は Zipf 分布の語の一節を繰り返す。速さは1更新16窓の測定から、1更新128窓（v7 の 100万トークン）に直した値。データの読み込み、重みの保存、検証は含まない。

## 文書ごとの注意

PyTorch の varlen の注意（FlashAttention-2）を、文書の境界を2のべき乗の数にそろえた形とそろえない形で、コンパイルあり・なしの両方で float32 の計算と比べた。12回ずつ試し、非有限の値はなく、出力と勾配の相対誤差は 0.4〜0.6% だった。v6 の測定でコンパイル後に NaN が出たのは、2回とも同じ1台の機械だった。

## 普通のモデル

| 形 | 精度 | 毎秒のトークン | メモリ |
|---|---|---|---|
| 約3.9億（v6 の形） | bf16 | 48,500 | 17.5GiB |
| 約3.9億 | FP8（注意の入力は bf16、テンソルごとのスケール） | 59,400 | 13.9GiB |
| 約3.9億 | FP8（行ごとのスケール） | 50,300 | 13.9GiB |
| 約7.2億（幅1280、40層） | bf16 | 28,900 | 27.7GiB |
| 約7.2億 | FP8 | 36,000 | 21.9GiB |

FP8 の4通りは、合成データで250回の更新を続けても非有限の値が出なかった。GPU の時間の内訳は、約3.9億の bf16 で行列の計算62%、注意18%、行列以外の細かい計算18%。

別の機械で、約3.9億の FP8 の学習の進め方を比べた。

| 進め方 | 毎秒のトークン | GPU が計算していた割合 | メモリ |
|---|---|---|---|
| 1窓ずつ、窓ごとに損失を取り出す | 57,600 | 69% | 13.9GiB |
| 1窓ずつ、損失を更新ごとにまとめて取り出す | 58,300 | 70% | 13.9GiB |
| 2窓ずつ、損失をまとめて取り出す | 62,600 | 81% | 21.1GiB |

## MoE

1トークンに使う大きさは v6 の形と同じにした（共有の専門家と選んだ専門家で 4,096 ユニット）。負荷は DeepSeek-V3 の偏りで均した。

- 1回目と2回目：二乗 ReLU の値が自動の精度切り替えで float32 になり、bf16 の専門家の行列との積で止まった。コードを直した。
- 専門家 512×24（7つを使う）と 256×48（14を使う）は、1窓ずつでも 32GB に収まらなかった。
- 専門家 1024×12（3つを使う）は、1窓ずつで 30.4GiB、毎秒 37,200 トークン。同じ機械の普通のモデル（2窓ずつ）の 64,100 より42%遅い。GPU が計算していたのは時間の53%だった。専門家ごとのトークン数を `torch.bincount` で数えていて、これが GPU を待たせているとみた（3回目で、原因ではないと分かった）。偏りを動かす速さ 0.001 では、120回の更新で全トークンが同じ専門家を選ぶようになった。
- 専門家の行列の FP8 は、PyTorch が計算能力 12.0 に対応していなかった。bf16 の専門家の計算は 159 TFLOP/s だった。
- 3回目：専門家ごとのトークン数を同期なしで数える形（scatter-add）に直し、偏りを動かす速さを 0.01 にした。1024×12 は、1窓ずつで毎秒 38,200 トークン、27.5GiB。同じ機械の普通のモデル（1窓ずつ）の 58,200 より34%遅い。GPU が計算していたのは51%のままで、待ちの原因は数え方ではなかった。モデル全体を1つの計算としてコンパイルするのに約12分かかった。偏りは変わらず、全トークンが同じ専門家を選ぶ状態になった。専門家を 1024×8 に減らしても、2窓ずつは 32GB に収まらなかった。

## 借りた機械

1回目の機械は、準備のダウンロードが止まった（28分で26/64のパッケージ）。SSH の鍵のファイルの持ち主か権限が sshd に拒まれる機械（「bad ownership or modes for file /root/.ssh/authorized_keys」）に2回当たった。コンテナの起動時に権限を直す処理を足すと、それ以降はつながった。
