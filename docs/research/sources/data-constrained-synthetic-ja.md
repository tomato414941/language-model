# Scaling Data-Constrained Language Models with Synthetic Data

Kiyomaru ら（EACL 2026 Findings、LLM-jp）。要旨、導入、節4〜6、結論、限界、付録 C を読んだ。図の数字は読んでいない。

日本語の Web が足りないときに、足りない分を何で埋めるかを比べた。予算は 72B トークンで、日本語の Web（FineWeb2 から 9B）を必ず使い、残りの 63B を次のどれかで埋める。書き手は Qwen3-14B（Apache-2.0）。

- 日本語の Web の言い換え。易しい文、Wikipedia 風、難しい文、会話の問答の4つの文体。
- 日本語の Web の文書の後に、その文書に基づく問答を足したもの。自由回答と選択式、それぞれ根拠の有無。
- 英語の Web（FineWeb）の日本語訳。
- 英語の Web。
- 同じ日本語の Web の繰り返し（8エポック）。
- 日本語の Web を 63B 足す（理想の比較）。

モデルは 1.8B、3.8B、7.2B。評価は llm-jp-eval の JSQuAD、NIILC、JEMHopQA、ALT（翻訳）で、選択式の課題は入っていない。

- 事前学習の後は、言い換えと問答が最も良く、日本語の Web を足した場合に並ぶか上回った。1.8B の平均は、繰り返し .410、英語の Web .347、言い換え .501、問答 .453、日本語訳 .411、日本語の Web を足す .462。7.2B では問答が .543 で、日本語の Web を足した .520 を上回った。
- 評価の課題の学習用データで3エポック調整した後は、差が縮んだ。1.8B は繰り返し .608、言い換え .641、問答 .653、日本語の Web を足す .639。3.8B は .652、.657、.661、.689 で、日本語の Web を足した場合が最も良い。
- 日本語訳は、1.8B では英語の Web より良かったが、3.8B と 7.2B ではほぼ差がなくなった。
- 評価の問題と学習データの重なりは、文字の16-gram で見てほとんどなかった。
- 著者らは、事前学習の後の差の一部は、指示に従う形を覚えたことによる可能性があるとしている。

データは Hugging Face の `llm-jp/scaling-data-constrained-llms`（CC BY 4.0）にあり、言い換え、問答、日本語訳がそれぞれ 63B トークン。

著者らは限界として、書き手が1つのモデルだけであることを挙げている。
