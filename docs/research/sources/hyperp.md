# Rethinking Language Model Scaling under Transferable Hypersphere Optimization（HyperP）

Ren ら（Microsoft）、arXiv 2603.28743（2026-03）。MoE の節（3.7）、実験の設定、負荷の均し方と MoE の節、付録の表 9〜11 と 16 を読んだ。公開コード（ArchScale の `lit_gpt/moe.py`、`lit_gpt/aux_loss.py`、`lit_gpt/model.py`、`pretrain.py`）で実装を確かめた。

重み行列を初めのノルムに保つ MuonH（[Hyperball](hyperball.md)）で、MoE を含めて学習率を規模の間で移す。

- **SqrtGate：** 選んだ k 個の専門家の出力を、点数 g（選んだ中で softmax、和が1）でなく √g で混ぜる。各専門家の出力の大きさが等しく、互いに相関しなければ、g で混ぜた出力は k が増えるほど 1/√k で小さくなり、√g なら k によらない。共有の専門家があるときは、選んだ専門家の和と共有の専門家の出力にそれぞれ √0.5 を掛けて足す。実験の MoE は全て SqrtGate と、選んだ専門家と同じ大きさの共有の専門家を1つ使う。
- **細かさ（表 11、疎さ 8）：** k = 2, 4, 8, 16, 32, 64 の最良の損失は、g で混ぜると 2.4306, 2.3263, 2.3220, 2.3178, 2.3186, 2.3244、√g で混ぜると 2.4131, 2.3262, 2.3156, 2.3111, 2.3096, 2.3154。√g は全ての k で良く、k = 32 まで良くなり続けた。最適な学習率は 0.012〜0.014 でほぼ変わらない。
- **構成（表 16、k = 8）：** 共有の専門家＋SqrtGate 2.3154、SqrtGate だけ 2.3210、共有の専門家だけ 2.3215。
- **router の安定：** 深さ16で、SqrtGate なしは router の logsumexp の2乗が約25から190超まで伸び、跳ねた。SqrtGate ありは40未満のまま。
- **均しの損失（表 3、9）：** Switch の形 γ·N·Σ fᵢPᵢ を層ごとに足す（コードで確かめた）。fᵢ と Pᵢ はデータ並列の全体で集める。γ = 0.001, 0.01, 0.1 の最良の損失は 2.334, 2.336, 2.332、最も使われた専門家の均等からの超過（層の平均）は 0.848, 0.132, 0.086。重みを保つと router の点が有界になり、強い均しが損失を悪くしないとみて、以後 γ = 0.1 を使う。
- **疎さ（表 10、k = 4、能動 208M、10.4B トークン）：** 全体を能動の 1, 2, 4, 8, 16, 32 倍にすると、損失は 2.4766, 2.4236, 2.3705, 2.3262, 2.2861, 2.2529。
- **実装：** router も他の行列と同じく MuonH で学び、PyTorch の既定の初期化（入力の数の平方根で縮める）を使う。専門家の大きさは、共有の専門家を含む k 個で密な MLP の単位を分ける。router の z-loss は記録するが損失には足さない。
