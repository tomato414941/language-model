# Compute Optimal Tokenization

Limisiewicz ら（arXiv 2605.01188、2026-05）。導入、節2、節3の結果の一部、節4の一部、節5、節6.1、節7、付録 D を読んだ。図の数字は読んでいない。

バイトから潜在のトークンを作る BLT を988モデル、BPE などを320モデル学習した。50M〜6.7B、5×10^18〜2×10^21 FLOPs。英語は DCLM で学習し C4 で評価、他の言語は FineWeb-2。指標は bits per byte で、HellaSwag も見ている。

- 「1パラメータ約20トークン」は決まった圧縮率を仮定している。安定するのはバイトで、英語は1パラメータ約60バイト（10^20 FLOPs で 62.1）。
- 10^20 FLOPs で1言語ずつ学習すると、最適は仏語 57.8、ベトナム語 61.2、英語 62.1、アラビア語 75.8、ヒンディー語 95.5、ロシア語 96.3 バイト。1バイトの情報が薄い言語ほど多い。
- 6言語を一緒に学習すると、どの言語も 68.9〜77.6 バイトにそろい、全体で約70バイト。このとき言語は情報量がそろうように混ぜている。言語ごとのデータが減るので、点は単独より悪い。
- 最適な1トークンのバイト数は、英語が単独で 3.71、6言語を一緒に学習して 3.38。情報が薄い言語ほど大きい。よく使われるトークナイザは、データの多い言語を圧縮しすぎ、少ない言語を圧縮しなさすぎる。
- BPE などでも最適のバイト数はほぼ一定とされている。当てはめの係数は B₀ = 2.8、N₀ = 0.059、α = 0.501、β = 0.446 で、ここから計算すると 10^20 FLOPs、3.71バイトで約45バイトになる（読んだ範囲に値はなく、こちらの計算）。

日本語と中国語は比べていない。節5の結果は 10^20 FLOPs だけ。学習率は計算量ごとに調整していない。
