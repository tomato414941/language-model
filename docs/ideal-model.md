# 理想的なモデルの作り方

理想的なモデルの作り方を本当に書くことはできない。ここに書けるのは、分かっていることだけである。

対象は、日本語と英語のモデルをゼロから少ない費用で作る場合。2026-11-02 までに分かったことを書いた。v6 の結果はまだ入っていない。新しいことが分かったら書き換える。見直し期限：2026-11-15。

各節の「言えること」は、その下の根拠から言える範囲の作り方で、正しいと確かめたものではない。根拠は次のように分ける。

- **測った：** 自分たちのモデルで測った。
- **報告：** 他の人の結果を読んだ。大きさ、データ、言語、読む量が違うことが多い。出典のメモは `research/sources/` にある。
- **計算：** 報告や測定の数字から、自分たちで計算した。
- **不明：** 分かっていない。

## 1. 先に測り方を決める

**言えること：** 公開の評価を提供者の形式で全問測り、判定の線は結果を見る前に決める。点と費用を並べて評価する。小さな差は読まない。

決めたこと。

- 公開されて広く使われている評価だけを使い、独自の評価は作らない。モデルの性能に合わせて形式を変えず、差がつかないときは、他の人が提供しているもっと簡単なテストを足す。間違っていると確かめた測り方は、過去と比べられなくなっても捨てる。
- 少ない予算は世代を上げる要件ではなく、改善を評価する点の1つ。

根拠。

- **測った：** v5 の点と問題数から計算すると、読める差は日本語8課題の平均で約 .013、英語12課題の平均で約 .009。問題の選び方の揺れだけで、学習の乱数の揺れは入っていない。21課題を差の標準誤差の2倍で判定すると、何も変わらなくても約4割の確率でどれかが下がったと出る。3倍なら約3%。
- **測った：** 点は答えの偏りで動く。JNLI は常に中立と答えると .555 になり、v5 はどの段階でもこれを超えず、矛盾が正解の735問を1問も当てていない。JCommonsenseQA は指示学習の後、印のない問いで1番目の選択肢に寄る。
- **測った：** 点は答え方の形式でも動く。1トークンだけ書かせる JMMLU では、v5 の返答の91〜98%が記号にならず、正解率は .004〜.020 だった。同じモデルで選択肢の文の確率を比べると .288 だった。
- **測った：** 損失と点は同じ向きに動くとは限らない。v5 の JCommonsenseQA の同じ400問で、安定期の最後から減衰期の最後まで、正解の選択肢の BPB は 1.009 から .766 に良くなり、正解率は .433 から .408 に下がった。差は10問ぶんで、偶然でも起きる大きさ。
- **測った：** 172問の M-IFEval-Ja は、同じ重みでも .163 と .186 に揺れた。
- **測った：** 学習の記録の検証は世代どうしで比べられない。世代ごとにランダムな64窓を読むからで、v5 の同じ最終の重みでも、64窓と検証データ全体で日本語 .553 と .524、英語 .66 と .639 と違った。同じ世代の中の推移は同じ窓なので比べられる。
- **報告：** 小さなモデルで比べるときは、正解率より尤度の指標のほうが信頼できる（DataDecide、Signal and Noise）。
- **不明：** 損失の差が、ベンチマークの点の差にどれだけ現れるか。

## 2. 計算をパラメータと読む量に分ける

**言えること：** 計算量（パラメータ×トークン）を決め、1パラメータ10〜20トークン（日英で約45〜90バイト）の間で分ける。この範囲なら配分の差は小さく、損失には計算の総量のほうが効く。ただ、計算を増やしても点の伸びは大きくないので、計算だけに頼らない。

読む量は、前の世代との比ではなく、そのモデルの大きさとの比で書く。

| 世代 | パラメータ | 読むトークン | 1パラメータのトークン | 1パラメータのバイト | 計算 |
|---|---|---|---|---|---|
| v5 | 3.0億 | 117億 | 39 | 約177 | 3.5×10^18 |
| v6（実行中） | 5.2億（value embeddings の表を除くと 3.86億） | 84億（うち56億は4トークンずつ） | 16（22） | 約70（95） | 1.6×10^18（表を除き、パッチを実際の計算に換算） |

パッチを実際の計算で数えると、v6 は通常の読み方で42億トークンに相当し、1パラメータ8（11）トークン、約35（47）バイトになる。パッチが効くかどうかで、どちらの数え方が正しいかが変わる。

根拠。

- **報告：** 計算量を固定したときの最適は、Chinchilla が1パラメータ約20トークン。Compute Optimal Tokenization は、20 はトークナイザの圧縮率に依存し、安定するのはバイトだとした。英語で約60バイト、1言語ずつでは 58〜96 バイト、6言語を一緒に学習すると約70バイト。nanochat の LOG は、value embeddings を入れると最適が8から4トークンに下がったとする。
- **計算：** Compute Optimal Tokenization の BPE の当てはめの係数からは、約45バイトになる。
- **計算：** 配分より総量が効く。パラメータ3.86億、1パラメータ11トークンを起点に、公開の2つの式（Chinchilla の当てはめ直し、ATLAS の英語）で計算すると、パラメータを固定して読む量を1パラメータ22トークンにすると損失は −.11〜−.14、計算量を固定して大きさを2.4億にすると −.01〜−.05。英語の損失の計算で、点ではない。
- **測った：** 読むほど損失は下がる。1.16億パラメータのモデルを続きで学習し、同じ検証データで測ると、1パラメータ8.5、26、112トークンで 1.106、.988、.875 bits/byte だった。検証データは最後のコーパスの混ぜ方に合わせてあり、後のモデルに少し有利。
- **計算：** 点の伸びは小さい。計算量（活性パラメータ×トークン）が2倍になるごとの7課題の平均の伸びは、HobbyLM の一族（活性6200万、10B トークンから、活性3.05億、100B トークンまで）で約 +0.8 点、SmolLM2（135M、2T トークンから、360M、4T トークンまで）で約 +2.9 点。読める差は英語で約0.9点、日本語で約1.3点なので、計算を2倍にして読める差になるかは境目。
- **報告：** 読む量だけで順位は決まらない。HobbyLM の表の4課題の平均で、v5（1パラメータ39トークン、英語はその半分）の 41.88 は、MicroLlama（167トークン）の 40.34 と OPT（514トークン）の 41.62 より高い。古いモデルも含む。HobbyLM は、順位はパラメータ数よりトークン数に沿うとしている。
- **不明：** 1パラメータ数十トークン以下の短い学習で、点を最大にする配分。日本語の点と読む量の関係。value embeddings の表をパラメータに数えるべきか。

## 3. 2つの言語で学習する

**言えること：** 言語を増やしても最適な比はほとんど変わらず、必要な計算が増える。損は日本語のほうが大きい。比率を細かく最適化する得は小さく、言語を読む順番の工夫は要らない。英語を増やすと日本語の点が上がるかは分かっていない。

- **報告：** ATLAS は、言語を r 倍にして損失を保つ計算は r^0.97 倍とした。
- **計算：** 同じ式で2言語にすると、計算は約2倍、パラメータ1.18倍、全トークン1.66倍。計算をそろえて比べると、最適な比は1言語の0.95〜1.04倍で、ほとんど変わらない。
- **報告：** ATLAS（2B の実測）で、半々で読むと、単独と同じ損失に届くのに日本語は1.3倍、英語は1.05倍のトークンが要る。中国語と読むと日本語は1.05倍。
- **報告：** 損は容量から来るとする報告が多く、大きなモデルほど小さい（Chang ら、ATLAS、Foroutan ら）。
- **報告：** 比率の最適化の得は小さい。He らの5つの語族で、均等と最適の損失の合計は 10.974 と 10.969。Schäfer ら（85M、1パラメータ14トークン）の英語と仏語の 90対10 は、多い言語を良くし、少ない言語を大きく悪くする。
- **報告：** 英語を増やす案には、賛成の結果がある。Foroutan ら（1.1B、3B）は、全トークンを固定して英語を50%以上に増やすと、他の言語の損失は悪くなるが下流の点は下がらないとした。Gamayun（1.5B、1パラメータ1000トークン以上）は、英語を37%から70%に増やす学習が、最初から70%以上より多言語の点で良く、英語でも追いつくとした。Kobayashi ら（13B、医療）では、英語のトークン数が日本語の課題とも強く相関し、日本の医師国家試験は日本語のトークン数と相関した。
- **報告：** 反対の結果もある。別の言語で学んだ事実を使える効率は、母語で学ぶ場合の 0.9〜5.9%（英語とアラビア語、ロシア語）。Saito らは、日本についての知識と英日翻訳は日本語のテキストで伸びるとした。
- **報告：** 言語を読む順番の工夫は、よく混ぜたものより良くならない（Foroutan ら）。
- **不明：** 日英の比率を変えて一般の点を比べた結果は見つけていない。1パラメータ数十トークン以下の短い学習での結果もほとんどない。

## 4. データ

**言えること：** データの質が効くので、出典の選び方に力を使う。中身を細かくフィルタしない。混ぜ方は小さな学習で比べて決められる。

決めたこと。データセットの中身を細かくフィルタしない。

- **報告：** 質の差は大きい。PreSelect は、選んだ 30B が選ばない 300B を上回るとした。Gamayun は、質の低いデータは質の高いデータの効果も下げるとした。Foroutan ら、Seto らは、言語を混ぜたときの悪化の一部を質の低いデータの影響とした。
- **報告：** データごとに得意な課題が違う。SmolLM2 の比較で、FineWeb-Edu は MMLU、ARC、OpenBookQA で高く、DCLM は HellaSwag と CommonsenseQA で高い。Web を書き直したデータと元の Web を半々に混ぜると、Web だけより良い（Niklaus ら、0.5B〜6.2B、英語）。
- **報告：** 混ぜ方は小さな学習で決められる。LLM-jp-4 は、小さな学習で13通りを比べて決めた。DataDecide は、150M の順位で 1B の最良を約80%当てた。SmolLM2 の小さなモデルでは、大きなモデルと違う結果になった。
- **報告：** 質の高いデータの繰り返しは、結論が割れている。10回まで良い、4回まで良い、繰り返すと悪くなる、の報告がある。v6 までは繰り返していない。
- **測った：** v5 と v6 のコーパスは出典ごとに並び、1つの窓の中がほぼ同じ出典になる。効果は測っていない。
- **測った：** v6 の日本語の減衰期は、文書の43%が LLM が書いた問答で、読んだ範囲に事実の誤りがあった。点への影響は分かっていない。
- **不明：** 日本語のコーパスどうしを比べた公開の数字は見つけていない。

## 5. トークナイザ

**言えること：** 少ない費用なら、語彙3万ほどの BPE で大きく外れてはいない。数字は1桁ずつに分ける。圧縮が良いほど良いわけではない。

- **測った：** 語彙32,768の BPE で、1トークンは日本語 1.65〜1.84文字、約4.9バイト、英語 3.20〜3.98文字、3.6〜3.9バイト。GPT-4 の区切りは、GPT-2 の区切りより要るトークンが3%少ない。
- **報告：** Compute Optimal Tokenization で、英語の最適は1トークン 3.4〜3.7 バイト。多言語で学習すると、単独より小さくなる。日本語は比べていない。
- **報告：** 圧縮が良いことは効率が良いことではない。From Tokens to Bytes では、区切らない BPE は6.03倍に圧縮したが、同じ損失に届く効率は、4.57倍の区切った BPE のほうが1.5倍良かった。
- **報告：** 語彙が大きいほど良いという研究もある。1T トークンの日本語の常識の課題の平均が、5k の 49.4 から 100k の 57.1 に上がった。語彙を増やすとパラメータが増えるので、短い学習で同じになるかは分からない。
- **報告：** 数字を1桁ずつに分けると、LLM-jp-4 で数学が良くなった。nanochat の BPB は1桁 .969、2桁 .965、3桁 .972。
- **不明：** 短い学習で、日本語に最適な語彙の大きさと圧縮。

## 6. モデルの形

**言えること：** 形の差は、大きさと読む量の差より小さい。報告の多い形から大きく外れなければよい。

v6 の形は、llama、幅1024、32層、8ヘッド（key-value は2ヘッド）、ReLU²、QK-norm、ゲート、value embeddings、学習するスカラー、出力のゼロ初期化。

- **報告：** 損失は幅÷層の広い範囲でほとんど変わらない。CompleteP の3億で、比23〜80の差は約0.3%。下流の点は研究によって結論が違う。
- **報告：** 個別の効果。ヘッド幅128は Marin の比較で BPB 1.2962 → 1.2838。QK-norm は IMU-1（7000万）で学習損失 −0.63%。value embeddings は nanochat で1層おきが最良で、ゲートが効いた。ReLU² は nanochat で SwiGLU より良く、Marin で差がなかった。出力のゼロ初期化だけを比べた結果は見つけていない。
- **測った：** どれも自分たちでは単独に測っていない。v6 はこれらを同時に入れたので、v6 の結果だけでは分けられない。
- **不明：** 組み合わせの効果。公開ベンチマークで幅÷層が30〜60の形を比べた結果は見つけていない。

## 7. 学習の進め方

**言えること：** NorMuon と cautious weight decay、1更新約100万トークン、最後の2割で学習率を下げる形は、報告の範囲で良い。パッチは費用を大きく下げるが、短い学習で点を保つかは分かっていない。

- **報告：** IMU-1（7000万）で、学習損失は AdamW 3.250、NorMuon 3.156、cautious weight decay を足して 3.125。
- **報告：** 1更新のトークンは、nanochat の外挿で34億〜96億トークンを読むモデルが約100万。学習率をバッチの平方根で上げる規則は検証が少なく、1更新 1M 以上では学習率を据え置くのが最良だったという報告がある（1.7B トークンの設定）。
- **報告：** 学習率の下げ方は結論が割れている。IMU-1 は最後の20%が最良で10%は下げないより悪く、LLM-jp-4 は下げる期間が長いほど良く、Straight to Zero は0まで下げるのがよいとした。
- **測った：** 4トークンずつ読むパッチの速さは 133,500 トークン/秒で、通常の 32,700 トークン/秒の4.08倍（RTX 4090）。
- **報告：** Shao らは、データの3分の2をパッチで読むと費用が半分で、370M の平均が 42.2 から 42.5 になったとした。1パラメータ約970トークン、AdamW、英語の結果。
- **報告：** 重みの平均は結論が割れている。IMU-1 は +0.014、LAWA は検証損失が下がり、nanochat は効かなかった。
- **測った：** RTX 4090 で FP8 は勾配が非有限になって止まった。原因は調べていない。bfloat16 は動く。コンパイルしないと1窓の勾配が 22.3GiB でメモリ不足になり、コンパイルすると 17.4GiB で動く。
- **測った：** 文脈を 8,192 から 32,768 トークンに伸ばしても、事前学習の後の平均は英語11課題で .366 と .367、日本語5課題で .404 と .399 でほとんど変わらなかった。費用は $3.61 増えた。
- **不明：** パッチが1パラメータ数十トークン以下の短い学習、NorMuon、日本語で効くか。

## 8. 指示学習

**言えること：** 指示学習ですべての点は上がらない。点の動きは答えの偏りと合わせて読む。指示学習の後は会話形式で測る。選択式の課題には、記号で答える学習を足す。

- **測った：** v5 の指示学習で、JSQuAD は .118 → .174、GSM8K は .017 → .033 に上がり、JCommonsenseQA は .390 → .309、JNLI は .542 → .470、BLiMP は .798 → .781 に下がった。下がったものの多くは、知識の低下より答えの偏りの変化で説明できる。
- **測った：** 文章や思考で答える会話を学習しただけでは、記号で答えられない。会話形式で問うと、記号で答えたのは KUCI で 10,291問中26問、JMMLU で 7,097問中478問だった。
- **報告：** HobbyLM は約150万会話の指示学習で、平均の点が 44.0 から 42.5 に下がった。
- **報告：** Kodama、Oda の1B級の比較で、指示と応答のデータを中間の学習で増やすと全体に点が上がる。コードの力は中間の学習でほぼ決まり、数学と推論は指示学習でも伸びる。
- **報告：** 計算をそろえると、言語ごとより言語をまとめた指示学習のほうが良いか同等（Chen ら）。
- **報告：** 指示学習の学習率は、事前学習のピークの13%（LLM-jp-4）、20〜40%（Muon と AdamW の切り替えの研究）。データ量の目安は見つけていない。7B と 8B では50万件まで点が上がり続けた。
- **不明：** v6 の2つの学習率と、記号で答える学習の効果。選好の最適化と強化学習が、この大きさで効くか。

## 9. 動かして記録する

**言えること：** 確かめてから進める。止まっても捨てない。書いたものは、あとで読んで分かるように書く。

- **測った：** RTX 4090 は約$0.40/時（2026-11 の Vast）で、3.86億パラメータなら1ドルで通常の読み方で約2.9億トークン、4トークンずつで約12億トークン読める。同じ GPU でも機械によって速さが違い、本番の機械は別の機械の91〜93%だった。
- 機械は借りたら中に入って動いていることを確かめる。自動削除は動作を確かめてから付ける。止まったら機械を残し、中を調べて続きから直す。できた部分から順に外に送る。
- 読む量は、そのモデルの大きさとの比で書く。前の世代の何倍と書くと、モデルの大きさが変わったときに意味が変わる。
- 時期は世代の名前か日付で書く。
- 自分たちで書いた文を決まりとして読まない。決まりは出所を確かめる。2026-11-02 に、予算と文書の繰り返しで、自分で書いた文を決まりと取り違えていたことが分かった。

## 10. 分かっていないこと

大事だと思う順に書く。

1. 読む量と点の関係。損失は下がるが、日英の点がどれだけ上がるか。
2. パッチが短い学習で効くか。
3. v6 の形と最適化の、個別の効果。
4. 英語の割合を変えると、日本語の点がどう動くか。
5. 日本語のデータの良し悪しが、点にどれだけ効くか。
6. 指示学習のデータ量と学習率の決め方。

v6 の結果は1〜3の手がかりになる。ただ、v6 は多くを同時に変えたので、結果だけでは分けられない。
