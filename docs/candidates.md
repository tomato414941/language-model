# 改善案

根拠の多くは他の人の結果で、費用は見積もり。調べた内容は `research/` にある。

## 指示学習をやり直すときの案

事前学習の重みから、約$2 で指示学習をやり直せる。

| 案 | 根拠と懸念 | 費用 |
|---|---|---|
| データの混ぜ方を計算で決める | 領域ごとにデータ量を変えた小さな学習から最適な重みを計算する研究がある。0.5B も比べていて、格子探索の最良との差は平均 0.66%。指標は検証損失で、下流の点の確認は 8B の表まで | 未見積もり |
| データの種類の組み合わせを測って決める | 干渉する1種類が他の効果を打ち消す例があり、小さなモデルの約24回の学習で選べて大きさをまたいで使えた。専門のコーパスの結果で、公開ベンチマークの点ではない | 未見積もり |
| 指示に従うデータを足す | M-IFEval-Ja と IFEval が低い。ただ量の不足とは言えない。全体は約52万会話で、指示に従う会話の割合は2.9%と Tülu 3 8B の3.2%に近い。増やして上がるという結果は見ていない。Nemotron-Instruction-Following-Chat-v1 の思考なしの約2万行か、v6 が 1.5万で止めている Tülu 3 の残りが使える。LIFT-Train も公開された（ライセンスと言語は未確認）。どれも日本語の同種の公開データではない | 指示学習が約$0.3 増える見込み |
| 事前学習のデータを混ぜる | v5 の指示学習で JNLI と JCommonsenseQA が下がったが、多くは答えの偏りの変化で、知識の低下とは言えない。BLiMP は下がった。LLM-jp-4 は中間の学習で半々に混ぜた。LoRA の報告では古い課題の例を混ぜると正解率が 5.43% でなく 97.83% に保たれ、新しい課題の点は変わらなかった。全体の学習で混ぜた例は未確認 | なし |
| データを小さなモデル向けに簡単にする | SmolLM2 の小さなモデルは複雑な指示と難問を除いた。ツール呼び出しは弱くなる | なし |
| 英語の思考を減らす | nemotron-v2-ja は予測するトークンの約86%が英語の思考。点への影響は未確認 | なし |
| 選好の最適化（DPO か APO-zero） | LLM-jp-4 が組を公開していて、コマンドはある | 約$2 |
| 強化学習（RLVR） | GSM8K と MGSM が低い。数学の報告は 1.5B パラメータ以上で、0.8B は検索の課題だけ。コマンドはある | 約$2 |

## 次の世代の候補

v6 はデータを固めたので入れなかった。次の世代は前の世代より安くなくてもよいので、点を上げる案に費用を回せる。次の世代を設計するときに見直す。見直し期限：2026-11-15。

| 案 | 根拠と懸念 |
|---|---|
| 文書を混ぜてからコーパスを作る | v5 と v6 のコーパスは出典ごとに並び、1つの窓の中がほぼ同じ出典になる。混ぜれば更新ごとの出典の揺れが減り、データ準備で費用はほとんど増えない。効果は未確認で、小さな実験で確かめられる |
| n-gram の計数を入力に足す（COUNT） | 60M〜1B で同じ計算の下流の点がほとんどの予算で上がり、検証損失は計算 46〜89% 増し、課題の損失は 6〜56% 増しに相当する。学習するパラメータは増えない。計数は Dolma 3 全体で、日本語と 8.4B トークンの計数では未確認。表の大きさと借りる機械のメモリの確認が要る |
| 対訳を読んでから普通に読む | 1.3B、120B で一般の点と翻訳の点が上がった。英仏と英スワヒリの結果で、日英の文書の対訳の公開データは未確認 |
| Bi-Phase Training | 1.5B で学習するパラメータ66%減、行列の層の計算が約3分の2、GPU メモリ 5.8GB 減、検証の対数 perplexity の差は 0.027。NorMuon では未確認 |
| 層ごとに回転の位置符号を割り当てる | 1B で検証損失が 2.785 から 2.758 に下がる。350M の差は 0.003。下流の点は未確認 |
| 学習率の下限を上げ、最後の重みと平均を混ぜる（TSA） | nanochat の d12 で BPB が約 0.0008 下がる。一様な平均は最後の重みより悪く、v6 の平均も一様。v6 の10個の重みは R2 に残るので、混ぜた重みの評価は学習なしでできる |
| 1更新 1M で学習率を平方根で上げない | 最適化の部門の設定（1.7B トークン）で、1M 以上では学習率の据え置きと weight decay の比例が最良。v6 は平方根で2倍にした。NorMuon では未確認 |
| 言語ごとに語彙を分ける | バッチごとに部分語彙の中だけでロジットを計算する。語彙の費用は 0.5B で1.58倍と小さなモデルほど大きく、語彙を増やす案と組み合わせられる。日本語の結果はない |
| 重みの大きさを制御する（Hyperball、MuonGS） | 2B で同じ損失に要る計算が16%減、MuonGS はさらに最大7〜15%。ただ Track 3 では NorMuon との差がなく、NorMuon と cautious weight decay の組み合わせと比べた研究はない |
| ORCA | 初めの25%だけ直交化の罰則をかける。350M と 1.3B で Muon より 0.02 低く、形は変わらない。数十トークン/パラメータ以上の結果で、v6 の16トークンの短い学習で追い越せるかは不明 |
| 学習率を下げ始めるのを遅らせる | v6 は減衰期のデータに切り替えると同時に下げる。630M では切り替え後の最後の40%で下げると、そのデータの損失が 0.014〜0.024 低い。IMU-1 の「最後の20%」と揃うかは未確認 |
| RTX 5090 とブロックごとの FP8 | 1.7B で速さ1.36倍、損失の悪化は 0.003〜0.004。Vast の最低価格は RTX 4090 の約1.37倍、dlperf は1.6倍、メモリは 32GB。学習の速さは未実測 |
| 文書の前のトークンを指すポインタ | speedrun の提案でステップが12%減り、約20万パラメータ増える。採用前で論文も未公開。下流の点は未確認 |
| 領域ごとに損失の重みを変える（LARE） | 1.5B で5つのベンチマークの平均が +7.84。追加の実行は要らない。要旨だけ読んだ |
| 形を 1152×24 にする | 計算が約8%減る（未実測）。幅÷層が最良とされる範囲に近い。KV の幅が 256 から 384 に変わる組み合わせを試した研究はない |
| 中断されうる GPU を使う | RTX 4090 で約28%安い。2026-10-24 の試しでは、最低額の15%増しの入札で数分ごとに止まった。重みが 6.2GB あり、R2 に頻繁に送ると転送料が増える |
| 易しい文書から読む | 0.5B、1更新108万トークンの比較でステップが18〜45%減り、点も最大3.5%上がった。英語と AdamW の結果。Puro-2B は質の低い順に読んで平均し、指示学習の後の15タスクの平均が 54.99 から 56.58 に上がった |
| 減衰期の英語の割合を増やす | Gamayun（1.5B）は英語を37%から70%に増やす学習で、最初から70%以上より多言語の点が良く、英語でも追いついた。英語と読むと日本語の損失は悪くなる（ATLAS）。1パラメータ1000トークン以上の結果なので、本番の大きさで比べる必要がある |
| 質の高いデータを繰り返す | 10回まで、4回まで良いという報告がある。v6 までは繰り返しておらず、読む量を増やすときに検討する |
| 語彙を65,536に増やす | 日本語で効くという研究は 1T トークンの結果。約1.7億パラメータ増える |
| 日本語の混ぜ方、日英の比率、コードと数学の割合を比べる | 日本語のコーパスを比べた公開の数字が見つからない。事実の知識は言語の間でほとんど移らないという結果と、英語を増やしても他の言語の下流の点は下がらないという結果がある（`research/topics/multilingual-training.md`） |
| 日本語 Wikipedia を増やす | LLM-jp-4 は Web の2倍の重みを付けた。直接の比較はない |
| decay の英語 Web を入れ替える | Ultra-FineWeb が FineWeb-HQ より上という報告がある |
| FineInstructions を足す | 1.8B で MixEval が約39%上。カードにライセンスの記載がない |
| コードと会話の合成データを足す | LLM-jp-4 の実験で HumanEval +2.82、MT-Bench +0.8 ほど。NVIDIA の規約の確認が要る |
| 日本語の合成データを混ぜる | LLM-jp が公開している、日本語の Web を Qwen3-14B で言い換えたデータを使う（CC BY 4.0、630億トークン）。日本語の Web が足りない設定の 1.8B〜7.2B で、同じ Web の繰り返しや英語の Web より良く、日本語の Web を増やした場合に並ぶか上回った。v7 に入れると決めた。割合は小さな実験で決める |
| 短い窓の層を混ぜる | 計算が約1割減る推定。点への影響の裏付けは弱い |
| パッチの割合を2分の1に減らす | 370M で 42.5→42.9。本番が約$3 増える |
| EMA-Nesterov | ステップ約6%減。NorMuon の結果は 124M だけで、メモリが重み1個分増える |
| SOAP-Muon | 目標の損失までのステップが約15%減（1.62億）。時間で得かは未測定 |
| MUDD、Attention Residuals | 論文では1.25〜2.4倍の計算量に相当するが、speedrun の MUDD は約3%。ブロックの変更が要る |
| Multiscreen | 同じ損失に要るパラメータが約30%減。ブロックから作り直し |
| H-Net（バイト入力） | 計算の効率が1.28〜2.06倍。日本語の数字はない。全面的な作り直し |
| FP8 | 効果は5〜10%の報告。RTX 4090 では勾配が非有限になって止まった。原因は未調査 |

## 方針に関わるもの

v6 には入れていない。入れるには、方針や規約を先に決める必要がある。

| 案 | 根拠と懸念 | 見直し期限 |
|---|---|---|
| ClimbMix を使う | nanochat で最大の短縮。CC BY-NC なので、非商用のデータを使うかを決める必要がある | 2026-11-15 |

## 入れないもの

調べたうえで、v6 には入れなかった案。期限の前に条件を見直し、変わらなければ期限を延ばす。

| 案 | v6 に入れない理由 | 入れる条件 | 見直し期限 |
|---|---|---|---|
| Soft-MTP | 167M と 332M では標準の MTP より約0.1点で、MTP なしを超えるのは 689M 以上。v6 は 520M | 689M 以上の世代 | 2026-11-15 |
| 合成データで先に学習する | 2026-09 と 2026-10 の研究で結論が逆 | 結論が揃う研究が出る | 2026-11-15 |
| 訓練データの検索で補う（speedrun の #367、#380） | 検証損失の結果で、読んだ範囲に下流の点がない。n-gram の計数は COUNT として次の世代の候補に移した | 下流の点で効くという報告が出る | 2026-11-15 |
| 本体の層で複数のトークンを予測する（ECHO） | 10B（活性 1B）を 600B トークン読んだ結果で、v6 の大きさとは桁が違う | 1B 以下の結果が出る | 2026-11-15 |
| 返答の割合で例を選ぶ | 細かいフィルタをしない決まり（`data.md`）に反する | 決まりを変える | 2026-11-15 |
| KUCI と JMMLU を選択肢の文の確率で測る | 提供者が定めた形式ではない。v5 の点は自前の定義で、外の点と比べられない | 提供者がその形式を定める、または決まりを変える | 2026-11-15 |
